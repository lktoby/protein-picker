# 機能一覧 — プロテイン比較・購入アプリ（仮称）

- 作成日: 2026-08-27
- 根拠: `docs/01-requirements/user-stories.md`（確認済みユーザーストーリー）、`docs/01-requirements/questions.md`
- 位置づけ: 開発フロー第1段階（要件定義）の成果物。各機能は「何を実現するか」を書き、実装方法・技術・画面構成には踏み込まない。

## 1. 機能一覧

| 機能ID | 機能名 | 概要（何を実現するか） | 対応ストーリー | 優先度 | スコープ |
|--------|--------|----------------------|---------------|--------|---------|
| F-01 | おすすめ条件の選択 | 飲む目的・飲みたいタイミング・その他のこだわり（乳糖不耐症対応など）を選択肢から選べる | US-01 | Must | 内 |
| F-02 | おすすめ商品の提示 | 選択した条件に合う商品を、おすすめ順に 1 件ずつ提示する。各商品に写真・ブランド・値段・1g あたりの価格・「なぜおすすめか」の 1 行の理由を添える | US-02 | Must | 内 |
| F-03 | 商品検索 | 商品名・ブランド名で商品を検索できる | US-03 | Must | 内 |
| F-04 | 商品情報の一気見（商品詳細） | 商品ごとに、値段（1g あたりの価格）・タンパク質含有率などの情報と、販売場所（ネット通販・実店舗）の一覧をまとめて見られる | US-04 | Must | 内 |
| F-05 | 実店舗情報の表示 | 実店舗での販売価格・店舗へのアクセス方法・連絡先を見られる | US-08 | Must | 内 |
| F-06 | 購入手続き（ネット通販・モック） | ネット通販で売られている商品を、アプリを出ずに購入手続きできる。ダミーの支払い入力フォームで購入を確定し、注文として記録する（実在の個人情報・支払い情報は扱わない） | US-05 | Must | 内 |
| F-07 | 注文履歴の表示 | 注文した商品を注文履歴画面で確認できる（アカウントなし。記録された注文を表示する） | US-06 | Must | 内 |
| F-08 | 商品お問い合わせ先の表示 | 購入した商品について、販売店舗のお問い合わせ先（メールアドレス・電話番号）を注文履歴などから確認できる（実際の送信・発信は行わない） | US-07 | Must | 内 |
| F-09 | サンプル商品データの整備 | 主要な種類（ホエイ／カゼイン／ソイなど）をひと通りカバーする 10〜20 商品程度のサンプルデータを備え、各機能（おすすめ・検索・詳細・購入）がそのデータで動作する | US-01〜US-08 の基盤 | Must | 内 |

## 2. カバレッジ確認（ユーザーストーリー → 機能）

| ストーリー | 優先度 | カバーする機能 |
|-----------|--------|---------------|
| US-01 条件を選びたい | Must | F-01 |
| US-02 おすすめを理由付きで見たい | Must | F-02（データは F-09） |
| US-03 商品を検索したい | Must | F-03 |
| US-04 商品情報を一気見したい | Must | F-04 |
| US-05 アプリ内で購入を完了したい | Must | F-06 |
| US-06 注文履歴を見たい | Must | F-07 |
| US-07 購入した商品について問い合わせたい | Must | F-08 |
| US-08 実店舗の情報を見たい | Must | F-05（詳細への導線は F-04） |

すべての Must ストーリーがいずれかの機能でカバーされている。

## 3. スコープ外機能（作らないもの）

| # | 機能 | 理由・根拠 |
|---|------|-----------|
| 1 | ネット通販・決済サービスとの実連携（Shopify・Stripe・e コマース API など） | モックのため（Q-01, Q-05） |
| 2 | 実在の個人情報・支払い情報の入力・保存 | モックのため。入力を誘導する機能も作らない（Q-02, Q-05, Q-12） |
| 3 | アカウント登録・ログイン | 不要（Q-09） |
| 4 | 複数商品を並べる比較機能 | 検索＋一覧・詳細で足りる（Q-10） |
| 5 | 検索結果・一覧の条件絞り込み機能 | 複雑になるため（Q-13） |
| 6 | 実際のメール送信・電話発信 | お問い合わせは連絡先の表示まで（Q-04 の解釈） |
| 7 | スクレイピング等による実在商品データの収集 | サンプルデータで賄う（Q-07, Q-11） |

## 4. 後工程への申し送り

- F-02 のおすすめ計算の仕組み（外部 AI API ／ ローカル計算）は `/design` で決定する（questions.md Q-07 の AI 補足参照）。
- F-02 のカード・カルーセル表示など具体的な UI/UX は `/prototype` で確定し `ui-spec.md` に記録する。
- F-06・F-07 の注文記録の保存方式（データベース利用。PostgreSQL への言及あり）は `/design` で確定する（Q-09）。
