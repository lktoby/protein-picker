# プロトタイプ説明（デモの見方）— プロテイン比較・購入アプリ

- 作成日: 2026-08-27
- 前提: 承認済みの要件定義（`docs/01-requirements/user-stories.md`, `feature-list.md`、2026-08-27 承認）
- デモコードの場所: `src/app/prototype/`（**捨てる前提の使い捨てコード**。本実装には流用しない）

## 1. 起動方法と入口 URL

```bash
docker compose up --build
```

起動後、ブラウザで **http://localhost:3000/prototype** を開く。

- 停止: `Ctrl + C` または `docker compose down`
- 事前にポート 3000 が空いていることを確認（`lsof -nP -iTCP:3000 -sTCP:LISTEN`）

## 2. 画面一覧と対応する機能

| 画面 | URL | 対応機能 | 対応ストーリー |
|------|-----|---------|---------------|
| ホーム（入口） | `/prototype` | — （導線のみ） | — |
| おすすめ診断（条件選択→カルーセル表示） | `/prototype/recommend` | F-01, F-02 | US-01, US-02 |

**Must 機能（F-01〜F-10）はすべて画面として触れる状態**（F-09 のサンプルデータは 12 商品を用意）。

> 注: F-10（お届け状況）は、デモレビュー RV-17 を受けて要件に追加された機能です（**要件の再承認待ち**）。

### おすすめの見方（推奨の回遊ルート）

1. `/prototype/recommend` で目的・タイミング・こだわりを選び「おすすめを見る」
2. カルーセル（←→）でおすすめを 1 件ずつ見る → 「詳細・購入方法を見る」
3. 商品詳細でネット通販・実店舗の価格を比較 → 「このショップで購入」
4. ダミーの支払い情報のまま「注文を確定する」
5. `/prototype/orders` で注文を確認 → 「お問い合わせ」で販売店舗の連絡先を表示

## 4. 仮置きした点（レビューで確認したい）

要件に書かれていなかったため、デモ作成時にこちらで仮置きした点です。**レビューで妥当か確認してください。**

1. **おすすめ条件の選択肢の中身**（仮置き）
   - 目的: 筋肉をつけたい／ダイエット・減量／健康維持・栄養補給
   - タイミング: 運動後／朝食時・朝／就寝前／間食・おやつ代わり
   - こだわり: 乳糖不耐症対応／植物性（ヴィーガン）／低糖質／国内製造／価格の安さ重視
2. **目的とタイミングは必須・単一選択、こだわりは任意・複数選択**にした。
3. **乳糖不耐症対応を選んだ場合、非対応商品はおすすめから除外**する仕様にした（減点ではなく除外）。
4. おすすめは**最大 5 件**表示。
5. 購入時の**数量選択（1〜5）**を付けた（要件に明記はないが購入体験として自然なため）。
6. 支払い方法はクレジットカード（ダミー）／コンビニ払い／銀行振込の 3 択にした。
7. 商品検索は**部分一致**（商品名・ブランド・風味・種類が対象）。
8. 実店舗の情報として営業時間も表示（要件はアクセス・価格・連絡先）。

## 4-2. レビュー後の変更履歴（2026-08-27）

初回レビューおよび AI クリティークを受けて、デモは以下のとおり更新済みです（詳細は `review-feedback.md`）。

- 診断条件を URL に保持し、商品詳細から戻っても結果が復元される（RV-02）
- 診断結果に「✓ 一致した条件」チップと順位の根拠の説明を追加。価格重視は実際の価格で採点（RV-09）
- 商品詳細のショップ一覧を価格の安い順に並べ「最安」バッジを表示（RV-11）
- **送料の内訳を明記**（商品代金＋送料／送料無料）（RV-16）
- **注文履歴にお届け状況を表示**（商品名の上をブランドから状況バッジに変更）（RV-17）
- 注文履歴の商品から商品詳細へ遷移できる（RV-10）
- 用語説明ページを追加（RV-04）
- ダミーカード欄を readOnly ＋「🎲 ダミー値をランダム生成」に変更（RV-08）
- ナビの現在地表示、カルーセルのスワイプ・矢印キー操作、タップ領域の拡大など（RV-06, RV-14, RV-15）

## 5. レビューで特に見てほしい観点

- **初心者の体験**: おすすめ診断 → 購入までの流れで迷う箇所はないか（US-01, US-02 の狙いが実現できているか）
- **一気見の十分さ**: 商品詳細に「これも出してほしい」という情報の不足はないか（例: 1食あたりの量、カロリーなど → あれば**要件の漏れ**として拾う）
- **カルーセルの操作感**: 1 件ずつ表示（Q-07 の要望）で比較しづらくないか。一覧との使い分けはこれでよいか
- **購入フロー**: ダミー決済の流れ・文言に違和感がないか（個人情報を求めない前提が守れているか）
- **お問い合わせ**: 注文履歴からの導線でよいか、商品詳細にも必要か
- 上記「4. 仮置きした点」の妥当性
