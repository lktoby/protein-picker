## 1. 全体・共通

- 画面構成: ホーム ／ おすすめ診断 ／ 商品検索・一覧 ／ 商品詳細 ／ 購入手続き ／ 注文履歴 ／ **用語説明** の 7 画面
- 共通ヘッダー: アプリ名＋「おすすめ診断」「商品をさがす」「注文履歴」「用語説明」の 4 ナビ（sticky）。**現在地のナビはアクティブ表示する**（RV-14）
- モックである旨・個人情報を入力させない旨の注意書きを常時表示（バナー）
- **`<html lang="ja">` とする**（日本語コンテンツのため）（RV-08①）。ページタイトル（metadata）はひな形のままにしない（RV-14）
- トーン: **モノクロ（無彩色）基調**の、余白の広いカード型 UI。**画面上の色は商品写真だけ**にする（2026-08-28 決定・§11-3）
  - ※ プロトタイプは「白基調＋エメラルドグリーン」だったが、これは AI が根拠を記録せず選んだ配色で、レビューでも議題になっていなかった（RV-01〜RV-18 に色の指摘はない）。§11-3 でモノクロに変更した
- **タップ対象（ナビリンク・小さなボタン類）は 44px 目安のタップ領域を確保する**（RV-14, RV-15）

## 2. おすすめ診断（F-01, F-02 / US-01, US-02）

- 条件選択（同一画面の上部）:
  - 質問は 3 つ。「目的」「タイミング」は必須・単一選択、「こだわり」は任意・複数選択。選択肢はピル型ボタン
  - 必須未選択の間は「おすすめを見る」ボタンは非活性
- おすすめ表示（同一画面の下部）:
  - **カード形式・カルーセルで 1 件ずつ表示**（要件定義 Q-07 で合意済み）。移動手段は「左右矢印ボタン」「ドットインジケーター」「**カードの左右スワイプ**」の 3 つを併存させる（RV-06）
  - ドット等の小さな操作要素は、見た目のサイズに関わらず**タップ領域を 44px 目安で確保**する（RV-06, RV-14）
  - カードの構成（上から順）: 商品写真＋「おすすめ N 位」バッジ → ブランド → 商品名・フレーバー → 価格（最安値・送料込み）・1g あたり価格・タンパク質含有率 → **送料の内訳（1 行）** → **✓ 一致した条件チップ** → 💡 1 行のおすすめ理由 → 詳細への導線ボタン（RV-09, RV-18①）
  - **価格の注記は「最安値・送料込み」のような書き方にせず、送料の金額を明記する**（RV-18①）。表示は `3,980円（内 送料 500円）`。送料 0 円なら `3,980円（送料無料）`、最安が実店舗なら `3,980円（店頭価格・送料なし）`。あわせて価格の下に「最安値: ショップ名」を添え、どこの価格かを示す
  - 結果見出しの直下に**順位付けの根拠の説明文**を表示: 「順位は『選んだ条件との一致度』と『価格（1g あたり・総額）』の総合で決まる」（RV-09）
  - **結果の下に「用語説明はこちら」リンク**を置き、用語説明ページ（§10）へ誘導する（RV-04）
  - おすすめは最大 5 件、順位付き。0 件時は「こだわりを減らして」と回復策を提示
- 状態の保持・フィードバック:
  - **診断条件は URL クエリに保持し、詳細ページから戻ったときに条件・結果を復元する**（RV-02）
  - 「おすすめを見る」実行後は**結果セクションへ自動スクロール**する（RV-05）
  - 結果表示後に条件を変更したら、**古い結果をグレーアウトして操作不可（キーボードフォーカス含む）にし**、警告バナー側に「新しい条件でおすすめを見る」再実行ボタンを置く（見た目と挙動を一致させる）（RV-05, RV-13, RV-15）
  - カルーセルは**キーボードの左右矢印キーでも移動できる**（フォーカス時はフォーカスリングを表示）（RV-15）
  - **不正な診断条件付きリンク**（存在しない目的・タイミング等）で開かれた場合は、黙って無視せず「条件が無効だったため復元できなかった」旨を通知する（RV-15）
  - こだわり質問の下に「用語がわからないときは用語説明へ」のヒントリンクを置く（RV-15）
- おすすめの採点方針（What レベルの確定事項）:
  - **「価格の安さ重視」を選んだ場合は、タグではなく実際の価格で総合評価する**。1g あたりが安いほど高評価、総額が高い商品は評価を下げる。理由文に総額を明記する（RV-09）
  - 乳糖不耐症対応を選んだ場合、非対応商品はおすすめから除外する（ハードフィルタ）
  - ※ 採点の計算方式そのもの（外部 AI API ／ ローカル計算）は `/design` で決定する

## 3. 商品検索・商品詳細（F-03, F-04, F-05 / US-03, US-04, US-08）

- 検索: 商品名・ブランド名等の部分一致。0 件時は検索語を引用したメッセージを表示
- 一覧カード: 写真・種類バッジ・ブランド・商品名・価格（送料込み）〜・1g あたり価格・タンパク質含有率
- 商品詳細（一気見）: 写真・ブランド・商品名・説明・種類/特徴バッジ＋スペック 4 点（最安値・1g あたり・含有率・内容量）→ ネット通販 → 実店舗（店頭価格・アクセス・電話・営業時間。0 件時はその旨表示）
- **ネット通販のショップ一覧は価格の安い順に並べ、最安のショップに「最安」バッジを付ける**（比較の結論を目視スキャンに委ねない）（RV-11）
- **戻り導線は遷移元に応じて切り替える**: おすすめ診断から来た場合は「← おすすめ結果に戻る」（診断結果へ復帰）、それ以外は「← 商品一覧に戻る」（RV-02）

## 4. 購入手続き（F-06 / US-05）

- 構成: ダミーである旨の警告 → 注文内容（商品・ショップ・数量 1〜5・合計〈送料込み〉）→ 支払い方法（クレジットカード／コンビニ払い／銀行振込）→ 確定ボタン → 完了画面（注文番号・要約・次アクション）
- クレジットカード選択時のダミー入力欄:
  - **入力欄は readOnly（編集不可）とし、実在のカード情報を入力できないようにする**
  - **「🎲 ダミー値をランダム生成」ボタン**でダミー値を差し替えられる（RV-08③・Q-05 で確定）
- **診断経由の文脈（from）は購入フローまで引き回す**: 「← 商品詳細に戻る」でも維持し、完了画面には「（診断経由なら）診断結果に戻る」を出す（RV-12）
- 確認ステップは追加しない（購入ページ内で注文内容を確認できるため冗長と判断。RV-03 見送り）。二重送信防止などのガードは `/design` で設計（RV-07）

## 5. 注文履歴・お問い合わせ（F-07, F-08, F-10 / US-06, US-07, US-09）

- 注文カード: 注文番号・日時・**お届け状況**・商品（画像＋商品名）・ショップ名・単価×数量＝合計・支払い方法
- **お届け状況（RV-17 / F-10・US-09）**:
  - 状態は「注文済み」「お届け中」「お届け済み」の 3 段階
  - **商品名の上には、商品のブランドではなくお届け状況を表示する**（ブランドは商品詳細で確認できるため）
  - 状態はバッジで表し、**アイコン・ラベル・「塗りの強さ」の 3 つで区別する**（モノクロ配色のため色相では区別しない。§11-3）
    - 注文済み = **枠線のみ**（塗りなし）／ お届け中 = **中間の塗り**（淡い面）／ お届け済み = **反転**（濃い面に明るい文字）
    - アイコンとラベルは常に併記する。**色相に依存しないため、色覚特性のある利用者にも 3 状態が区別できる**
  - 注文直後の状態は「注文済み」。購入完了画面にも「お届け状況: 注文済み」を表示する
  - 状態をどう更新するか（管理側の操作・外部連携など）は `/design` で設計する。**利用者が自分で状態を進める画面は作らない**
- **注文カードの商品部分をクリックすると商品詳細ページへ遷移する**（「商品詳細を見る →」の明示リンク付き）（RV-10）
- 「お問い合わせ」ボタンで、その注文の販売ショップの連絡先（メール・電話）をアコーディオン表示（1 件のみ展開）。実際の送信・発信は行わない
- 注文が 0 件のときは空状態メッセージ＋導線を表示。**第一 CTA は主導線の「おすすめ診断」、第二 CTA に「商品をさがす」**（RV-15）

## 6. 価格表示ルール（RV-01・全画面共通）

- **表示価格はすべて「送料込み」に統一する**（toby 決定・2026-08-27）。一覧・詳細・購入画面にその旨を明記する
- **「送料込み」で終わらせず、必ず送料の金額を明記する**（RV-16, RV-18①）。**価格を表示するすべての箇所に適用する共通ルール**:
  - 合計金額の注記: `3,980円（内 送料 500円）`。送料 0 円は `（送料無料）`、実店舗の店頭価格は `（店頭価格・送料なし）`
    → 適用箇所: **おすすめカード・商品一覧カード・商品詳細のスペック欄（最安値）**
  - 商品詳細のショップ行: 総額の下に `商品 3,480円 + 送料 500円`、送料が 0 円のショップは「**送料無料**」を強調する（モノクロ配色のため、色を変えるのではなく**太字＋淡い面のチップ**で目立たせる。§11-3）
  - 購入画面の合計: 「商品代金（単価×数量）／送料／合計」の 3 行の内訳として表示する
  - 実店舗の欄: 「店頭でのお渡しのため送料はかかりません」と明記する
  - 送料はショップごとに決まる値として持つ（商品ごとではない）
- 価格には常に **1g あたり価格を併記**する（容量が異なる商品を公平に比較するための本アプリの中核指標）
- **「最安値」の定義: ネット通販・実店舗を含む全販売チャネルの最低価格（送料込み）**。一覧の「〜」表記と詳細の「最安値」は同じ定義で扱う
- **記号の表記ルール（RV-18②）**: 金額・数量の式に使う記号は**半角**に統一する（`商品 3,480円 + 送料 500円`、`1,000円 × 2 = 2,000円`）。日本語の語と語をつなぐ用法（例: 「ホエイ＋ソイのバランス型」）は全角でよい

## 8. 踏襲しなくてよい部分（デモの割り切り）

    参考: 現在このプロジェクトには UI コンポーネントライブラリ・アイコンライブラリは未導入（Tailwind CSS v4 のみ）。
- 注文のメモリ上保存（リロードで消える）→ 本実装ではデータベースに保存（`/design` で確定）
- **注文履歴の「🔧 デモ用: お届け状況を次に進める」リンク** → レビューで 3 つの状態を確認できるようにするためのデモ専用の操作。**本実装では作らない**（状態は管理側・外部連携で更新される。§5 参照）
- バリデーション・エラー処理・ローディング表示の作り込み
- フォント（ひな形既定の Arial）→ 本実装でフォント選定を行う（`/design` で決定）

## 9. `/design` で決めること（この工程では決めない）

## 10. 用語説明ページ（RV-04 / F-02 の補助）

- 位置づけ: 初心者が用語（ホエイ／WPI／カゼイン／ソイ／ミックス）や数値の意味で置き去りにならないための独立ページ
- 導線: ①ヘッダーナビの「用語説明」ボタン ②おすすめ診断の結果下の「用語説明はこちら」リンク（Q-04 の指定どおり）
- 内容:
  - プロテインの種類 5 つ: それぞれ 1〜2 行の説明＋「こんな人に」の一言
  - 数値の見方: タンパク質含有率の目安（65〜75% が一般的・85% 以上は高純度）、1g あたり価格の目安（送料込み）
  - 乳糖不耐症の説明と、対応する種類（WPI・ソイ）・診断での絞り込み方法
  - 医学的助言ではない旨の注記
- ページ末尾に「おすすめ診断をやってみる」「商品をさがす」への導線を置く（読んだ後に行動へ戻す）


## 11. 改訂記録（`/design` 工程での追加・修正）

この文書は `/prototype` のレビューで確定したものだが、以下は**その後 `/design` 工程でユーザーの要望・指摘を受けて改訂した項目**である。
勝手な変更ではないことを示すため、日付・決定者・理由を明記する。**視覚的な結果は `/implement` で実際の画面を見て確認する。**

### 11-1. ダークモードの導入（2026-08-28・toby 要望）

- **決定: ダークモードを導入する。** ライト／ダーク／OS 設定に追従の 3 状態を切り替えられるようにし、ヘッダーに切替コントロールを置く
- 経緯: `/design` 工程でユーザーから導入の要望があった。要件定義に戻していない理由は、**新しい情報や業務機能を増やさない**ため（RV-17 のお届け状況は新しい情報だったので要件に戻したが、ダークモードは同じ内容の見せ方の選択肢にあたる）
- §1 の「基調」は**ライトモードの指定**として読み替える。ダークモードでは暗い背景に読み替えた対応値を使う
- **配色は「意味のトークン」で定義する**（`background` / `foreground` / `card` / `muted-foreground` / `border` / `primary` など）。個々の画面に明暗 2 種類の色指定を書き分けない
- 具体的な値は §11-3（モノクロ配色）の表を参照
- **切替コントロール（2026-08-28 決定・`questions.md` Q-05）**:
  - **ヘッダー（メニューバー）にアイコンボタンを置き、クリックでライト ⇄ ダークを切り替える**
  - **初期状態は OS の設定に従う。** 利用者が一度クリックしたら、その選択を記憶して優先する
  - アイコンは現在のモードに応じて切り替える（ライト時は「ダークにする」意図のアイコン、ダーク時はその逆）。アイコンのみでも用途が伝わるよう `aria-label` を付ける
  - `ui-spec.md` §1 の「タップ領域 44px」を満たすサイズにする
- 個別に手当てする箇所: **お届け状況バッジの 3 段階**（§5・塗りの強さで区別）、モック注意バナー・ダミー決済の警告（§1・§4）、**商品画像**（暗背景で写真が浮かないよう枠を敷く）、**フォーカスリング**（明暗どちらでも視認できること。§2 の RV-15 の約束を維持）
- 実装方式は `docs/03-design/screen-flow.md` §1-3 に記載

### 11-2. 主ボタンのコントラスト修正（2026-08-28・AI 計測による指摘）→ **§11-3 のモノクロ化で解消**

- **問題**: プロトタイプの主ボタン（`bg-emerald-600` に白文字、13 箇所）のコントラスト比は **3.77:1** で、**WCAG AA（本文 4.5:1）を満たしていない**。ボタンの文字は 14px 太字であり「大きい文字」の緩和（3:1）は適用されない
- **修正: 主ボタンの背景を `emerald-700` 相当にする**（白文字とのコントラスト **5.48:1**、AA 適合）。見た目はわずかに濃い緑になる
- レビュー済みの外観を変えることになるが、**これは好みの変更ではなくアクセシビリティ上の欠陥修正**として行う
- **追記（2026-08-28）: §11-3 でモノクロ配色に変更したため、緑の主ボタン自体が無くなり、この問題は解消した。** モノクロの主ボタン（濃い面に明るい文字）のコントラストは **17.93:1** で、AAA を大きく上回る。この節は経緯の記録として残す

### 11-3. モノクロ配色への変更（2026-08-28・toby 決定 / `questions.md` Q-04）

**決定: 配色をモノクロ（無彩色）にする。** プロトタイプの緑・白から変更する。

- 変更した理由: 緑・白は**この分野のカテゴリ既定色**（プロテイン・サプリのサイトはほぼ緑）で、意図して選ばれたものではなかった（§1 の注記参照）
- **「モノクロ」の解釈: グレースケール（無彩色）とする。** アクセントとして 1 色を足すことはしない
- **設計意図: 画面上の色は商品写真だけにする。** UI が無彩色に退くことで、商品の写真だけが色を持って際立つ。比較・購入アプリとして「商品を見せる」ことに一貫させる
- **画面構成・操作方法・情報の見せ方は一切変えない。** 変えるのは色の値だけ（§1〜§10 の仕様はそのまま有効）

#### 強調の作り方（色相を使わずに階層を作る）

モノクロでは色で目立たせられないため、**塗りの強さ・文字の太さ・余白**で階層を作る。

| 役割 | 表現 |
|------|------|
| 主ボタン（最も強い操作） | **濃い面に明るい文字**（反転） |
| 副ボタン | **枠線のみ**（面は塗らない） |
| 第三の操作・リンク | **文字だけ**（下線） |
| 強調したい情報（「最安」「送料無料」など） | **太字 ＋ 淡い面のチップ** |

#### 配色トークンと実測コントラスト

無彩色のため `neutral` 系（色味のないグレー）を使う。**すべて WCAG AA 以上を実測で確認した。**

| トークン | ライト | ダーク | 実測コントラスト |
|---------|-------|-------|---------------|
| `background`（ページ地） | `neutral-50` | `neutral-950` | — |
| `card`（カードの面） | `white` | `neutral-900` | — |
| `foreground`（本文） | `neutral-900` | `neutral-50` | **17.93:1** ／ **17.18:1**（AAA） |
| `muted-foreground`（補助テキスト） | `neutral-500` | `neutral-400` | 4.74:1 ／ **7.11:1**（AA 以上） |
| `primary`（主ボタンの面） | `neutral-900` | `neutral-50` | 文字とのコントラスト **17.93:1** ／ **17.18:1**（AAA） |
| `border`（装飾的な区切り線） | `neutral-200` | `neutral-800` | 装飾なので低コントラストで可 |
| `input`（**入力欄の枠線**） | `neutral-500` | `neutral-500` | 4.74:1 ／ 3.78:1（**どちらも 3:1 以上**。入力欄の枠は操作対象の境界なので 3:1 が必要） |
| `ring`（フォーカスリング） | `neutral-900` | `neutral-50` | 17.93:1 ／ 17.18:1（RV-15 の約束を満たす） |

> `input` は**明暗で同じ値（`neutral-500`）が両方の基準を満たす**ため、1 つの値で足りる。

#### お届け状況バッジ（§5）の 3 段階

色相ではなく**塗りの強さ**で区別する。アイコンとラベルは常に併記する。

| 状態 | 表現 | 実測コントラスト（ライト） |
|------|------|---------------------|
| 注文済み | **枠線のみ**（塗りなし） | 7.81:1（AAA） |
| お届け中 | **淡い面**（`neutral-200`）に濃い文字 | 14.23:1（AAA） |
| お届け済み | **反転**（濃い面に明るい文字） | 17.93:1（AAA） |

**これは色版より優れている点がある**: 色覚特性のある利用者でも 3 状態を区別できる（元の案はグレー／青／緑で、色相のみに依存していた）。

#### モノクロで失うものと、その補い方

| 失うもの | 補い方 |
|---------|--------|
| **警告の琥珀色**（モック注意バナー・ダミー決済の警告。§1・§4） | **反転バー**（濃い面に明るい文字）＋警告アイコン＋太字にする。モノクロでは反転が最も強い強調になるため、色に頼らずとも十分目立つ |
| **エラー表示の赤** | 反転の面＋エラーアイコン＋太字。文言で明確に伝える（`api-spec.md` §1-4 のとおりエラー文は日本語で理由と回復手段を示す） |
| **「送料無料」の色替え**（§6） | 太字 ＋ 淡い面のチップ |
| **緑が与えていた「健康的」な連想** | 商品写真・タイポグラフィ・余白で作る。UI が無彩色に退くことで写真の訴求力は上がる |

> **注意（`/implement` で確認する）**: 警告・エラーを色で区別しない設計は、**アイコンと文言が確実に伝わることが前提**になる。実装時に「これが警告だと分かるか」を実画面で確認する。分かりにくければ、警告のみ例外として 1 色を許容するか再検討する（その判断もこの文書に追記する）。
